    Core & builders¶

    The graph and action model you assemble, the builder/layer stack that runs it, and the reporters, results, and workspace loaders around it.

    Brix's supported Python authoring and extension API.

    Engine implementation types live in their defining modules and are not part of the top-level v1 contract. See docs/python-api.md.

    Graph ¶

    Graph()

    A logical build graph.

    Holds action declarations. The engine normally infers dependencies from data-set intersections; force_order covers the exceptional case where actions must be ordered without sharing data.

    force_order ¶

    force_order(
    before, after, *, trigger=EdgeTrigger.ON_SUCCESS
)

    Require before to finish before after may run.

    This is for ordering with no data relationship; ordinary file/data dependencies should remain implicit. Both actions must already have been added to this graph exactly once.

    ExternalProcessAction ¶

    ExternalProcessAction(
    name=None,
    *,
    command_line,
    inputs=None,
    outputs=None,
    env=None,
    env_used=None,
    worker=None,
    depfile=None,
    self_resolved_inputs=(),
    _env_used_snapshot=None
)

    Bases: Expandable

    A generic external process.

    command_line is a template whose {placeholder} names refer to entries in inputs and outputs. Binding placeholders such as {name} inside data-expression paths belong to a separate namespace and are substituted at expansion time, not at command rendering time.

    name is diagnostic identity: node labels, echo lines, and process results. It is optional; unnamed actions are labeled by their command template. Named actions will fingerprint/debug better once incremental metadata and caching exist.

    substitute ¶

    substitute(bindings)

    Return a concrete copy with bindings applied to name and data paths.

    ExpandAll ¶

    ExpandAll(element_name, collection, child)

    Bases: Expandable

    Repeated work over a data collection.

    Not an opaque loop: this is an unrealized expansion point in the execution plan. Once collection membership is known, it expands into concrete sibling nodes, one per binding of element_name.

    The child is any Expandable — a process action, or another ExpandAll for nested repetition (per video, per scene of that video); use distinct element names per level.

    substitute ¶

    substitute(bindings)

    Apply outer bindings. If they bind this expansion's own element (target selection does), the expansion collapses to its substituted child — there is nothing left to expand over.

    Expandable ¶

    Bases: Action

    Anything an ExpandAll can instantiate per collection member.

    Requires a diagnostic label and binding substitute. Both ExternalProcessAction and ExpandAll itself qualify — so expansion points nest: an outer expansion over videos can instantiate an inner expansion over each video's scenes.

    EdgeTrigger ¶

    Bases: Enum

    When an edge lets its target proceed.

    ON_SUCCESS is the default: the source must be DONE, and a failure cascades a skip. ON_COMPLETION fires whether the source succeeded or failed — for cleanup that must run because its trigger failed.

    CleanBuilder ¶

    CleanBuilder(graph, root='.')

    Bases: NestableBuilder

    Builds everything the graph declares; no change detection.

    layer_specs ¶

    This builder's layer stack as boundary-schema configs (innermost first), or None when it holds something that can't cross (a custom Python store object). Mirrors layers().

    worker_idle_timeout: seconds a persistent worker's daemon stays warm between builds (default 900; 0 = no daemon). Rust engine only; the Python engine always terminates workers at build end.

    IncrementalBuilder ¶

    IncrementalBuilder(
    graph_supplier,
    root=".",
    metadata_dir="build/.brix",
    detector=None,
)

    Bases: NestableBuilder

    Skips work whose fingerprints prove it up to date.

    graph_supplier is a callable so the builder decides when and how much graph to load (a plain Graph is also accepted). Metadata lives under metadata_dir; if it is missing the build degrades to clean behavior and records everything for next time.

    CacheBuilder ¶

    CacheBuilder(inner, cache_dir=None, store=None)

    Bases: NestableBuilder

    Reuse results across workspaces and clean checkouts.

    Wraps another builder; the cache layer sits innermost, keyed by the same action_fingerprint the incremental layer records.

    Backing store, pick one:

    • cache_dir (default) — the built-in local CacheStore under this directory. Absolute for a cache shared between checkouts, or workspace-relative; keep a relative one under a .brix-prefixed directory (the default) so workspace scans ignore it.
    • store — any object with the CacheStoreProtocol three methods: a remote team cache, or a TwoTierCacheStore fronting one with local disk. An unreachable store degrades to a cache miss (handled in the layer), never a failed build.

    Passing both is an error.

    AtomicBuilder ¶

    AtomicBuilder(inner, staging_dir='build/staging')

    Either the whole build lands, or nothing on disk changes.

    Wraps another builder; its layer sits outermost, so process outputs and (later) cache-restored outputs all pass through staging. It is intentionally not a NestableBuilder — nothing may wrap it (see that class), so it is always the outermost builder.

    build ¶

    build(
    jobs=None,
    reporter=None,
    targets=None,
    hold=False,
    worker_idle_timeout=None,
)

    hold=True: build fully but keep outputs in staging for review — the workspace changes only at commit. worker_idle_timeout: see IncrementalBuilder.build.

    commit ¶

    commit()

    Apply held staging to the workspace. None if nothing is staged; (files, deletions) otherwise. Raises ValueError on failed-build staging, which must never reach the workspace.

    discard ¶

    discard()

    Throw staging away, workspace untouched. None if nothing is staged; the number of files discarded otherwise.

    NestableBuilder ¶

    Marker for a builder another layer may legally wrap.

    AtomicBuilder is deliberately not a NestableBuilder: its layer establishes the staging overlay and its build() carries the P0 staging hazard guard and the commit/discard workflow, so it must be the outermost builder. Because the wrapping builders type their inner as NestableBuilder, a type checker (mypy/pyright, and so any IDE) flags CacheBuilder(AtomicBuilder(...)) as it is typed; __init__ also raises at runtime, since Python type hints are not enforced. The language-neutral form of this rule — atomic is the outermost layer in the wire spec — is validated in the Rust core, so every future frontend inherits it (see docs/boundary-schema.md).

    BuildLayer ¶

    Hook interface for build capabilities. All hooks are optional.

    Layers never touch plan structure or node state directly; they obtain results (around_node), adjust the context, and propose work through the scheduler.

    on_build_begin ¶

    on_build_begin(plan, ctx)

    Build is starting (e.g. prepare staging, recover a crashed build).

    around_node ¶

    around_node(node, ctx, inner)

    Obtain the node's result: answer without calling inner (skip / cache hit), adjust ctx before passing the call inward, or both.

    on_collection_realized ¶

    on_collection_realized(node, members, ctx)

    An expansion point's membership just became known.

    May return node proposals (e.g. stale-output deletions); the scheduler inserts them and orders them before the collection's consumers.

    on_build_end ¶

    on_build_end(result, ctx)

    Build finished (e.g. commit staged outputs if everything succeeded).

    NodeContext dataclass ¶

    NodeContext(
    workspace_root, output_root, deletions_root=None
)

    Where one node's execution reads and writes.

    Declared paths on actions are logical names; the context maps them to physical places. With no layers both roots are the workspace. The atomic layer points output_root at its staging tree and deletions_root at its deletion markers — reads then see the workspace as it will look after commit: staged outputs shadow workspace files and marked deletions hide them (the overlay).

    read_path ¶

    read_path(logical)

    The physical location a logical path currently reads from.

    find ¶

    find(pattern)

    Realize a PathPattern across the overlay.

    Returns (logical path, physical path, bindings), staged copies shadowing workspace copies, marked deletions excluded.

    iter_files ¶

    iter_files()

    Every (logical, physical) file visible through the overlay, excluding brix's own storage (staging tree, metadata dirs).

    NodeProposal dataclass ¶

    NodeProposal(action, label=None)

    Work a layer proposes; the scheduler inserts and wires it.

    This is the insertion channel from the layer side: layers never touch plan structure. Proposals returned from on_collection_realized are ordered before the collection's consumers.

    ConsoleReporter ¶

    ConsoleReporter(stream=None, show_replays=True)

    Bases: Reporter

    Live output as the build runs — the classic make-style stream.

    Results that were not produced by a fresh process are marked with their provenance, e.g. ok: compile foo (replayed). Pass show_replays=False to print only real work: successful replayed results are suppressed entirely (replayed failures still print).

    Workspace dataclass ¶

    Workspace(
    root,
    packages,
    graph,
    depends_on=dict(),
    footprints=dict(),
    patterns=dict(),
    full_load=True,
)

    A loaded hierarchical workspace: its packages, their merged graph, the ownership map, and the derived cross-package dependency index. graph plugs straight into the existing builders (it is an ordinary merged Graph). owner_of maps a changed path to its package; dependents_of (the reverse of depends_on) is what a later tier will walk to load only the packages an edit touches — "package P changed → also load its dependents." Nothing consumes the index yet, so there is no staleness surface here; it is derived and (optionally) persisted for tiers 2b/3.

    dependents_of ¶

    dependents_of(package)

    Packages that depend on package (the reverse index): if this package's files change, these must also be loaded/rebuilt.

    save_index ¶

    save_index(metadata_dir='build/.brix')

    Persist per-package input/output patterns, footprints, and the cross-package dependency edges (repo-relative), so a later build can decide what to load without loading — or re-deriving — anything.

    Merges with an existing index: entries are written for the packages this workspace actually loaded (self.patterns), entries for packages that no longer exist are dropped, and entries for discovered-but-unloaded packages are kept as-is — so a subset load refreshes its slice without clobbering the rest. last_selected records the loaded set, the recovery anchor after a failed build.

    Edges are the performance-critical part. Deriving them is O(packages² × patterns), so they are computed once on a full load (where depends_on is complete and authoritative) and persisted; a later subset build reads them O(packages) instead of re-deriving. A subset save carries the persisted edges forward — sound because a subset build only happens when no brix.py changed, so patterns are stable — unless a footprint-driven reload actually changed a loaded package's input/output patterns, in which case the edges are dropped so the next build full-loads and heals them (edges depend only on the patterns).

    WorkerSpec dataclass ¶

    WorkerSpec(name, command_line, inputs=dict())

    How to launch a worker. command_line renders (like an action's) from inputs into the worker's launch argv; name is diagnostic identity.

    build_stack ¶

    build_stack(
    graph_supplier,
    root=".",
    *,
    metadata_dir="build/.brix",
    cache_dir="build/.brix-cache",
    store=None,
    staging_dir="build/staging",
    detector=None
)

    Assemble the standard builder stack in the correct order — AtomicBuilder(CacheBuilder(IncrementalBuilder(...))) — so the ordering can't be gotten wrong (atomic outermost; see NestableBuilder).

    Layers toggle by argument: pass cache_dir=None (and no store) to drop the cache, staging_dir=None to drop atomic staging (e.g. a cross-module compiler that self-resolves its classpath, which atomic staging can't support — see examples/kotlin_multimodule). detector is the change-detector factory threaded to the IncrementalBuilder (e.g. GitChangeDetector); None uses the default stat detector. Defaults give the full recommended stack.

    Returns a builder; for cli.main's builder_factory (called fresh per invocation, so commit/discard rebuild cleanly), pass a thunk::

    cli.main(create_graph, builder_factory=lambda: build_stack(create_graph, root=ROOT))

    load_workspace ¶

    load_workspace(
    root,
    *,
    brix_file="brix.py",
    graph_attr="create_graph",
    only=None
)

    Discover every package under root, load each package's graph, and merge them. Returns a Workspace; ws.graph is a plain merged Graph usable with any builder — e.g.::

    ws = load_workspace(ROOT)
cli.main(lambda: load_workspace(ROOT).graph, root=ROOT, ...)

    only (a set of package directories) is the subset-loading primitive: only those packages' graphs are loaded and merged, for a build that touches just part of the workspace. It is deliberately mechanical — it loads exactly what it is told; deciding which packages are the affected set (so the partial build is complete, not stale) is the lazy-loading tier's job, proven by the equivalence oracle. Unselected packages' outputs are assumed already present and fresh on disk (from a prior full build). packages still lists every discovered package (for ownership); the cross-package index is derived only on a full load — a subset build consults the persisted index via load_index, never a partial re-derivation.

    A package whose build file lacks graph_attr is skipped (it may be a standalone entry point that only wires cli.main, not a graph contributor).

    load_affected ¶

    load_affected(
    root,
    changed=None,
    *,
    brix_file="brix.py",
    graph_attr="create_graph",
    metadata_dir="build/.brix"
)

    Load only the packages affected by changed (or by what git reports changed since the last build, when changed is None) — falling back to a full load_workspace whenever completeness cannot be proven.

    Either way the persisted index is refreshed for every package actually loaded (Workspace.save_index merges, so a subset load never clobbers the other packages' entries), and last_selected is written at load time — before the build runs — so a build that fails midway can be recovered by the next selection.
