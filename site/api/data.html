    Data model¶

    Every action declares its inputs and outputs as data expressions: concrete files, globs, values, and tools. Brix infers dependency edges from where these overlap, so the data model is how you tell Brix what a step touches. In build files you usually construct them through a graph's data factory (g.data.file(...), g.data.glob(...)), documented here as DataFactory.

    Logical data expressions.

    These are the user-facing declarations of what data exists: files, file collections, tools, and literal values. They are clean-build truth — they say nothing about caching, staging, or incremental state.

    DataExpr ¶

    Base class for all logical data expressions.

    DataAtom ¶

    Bases: DataExpr

    A leaf data expression.

    content_key is the atom's comparison semantics: the name of the content lens fingerprinting compares it through (e.g. "jvm-abi"). None — the default for a plain file/glob — is byte hashing. It is intrinsic to what the datum is (like the File/Tool/Value distinction), so a lens is a typed subclass (brix.java's AbiFile/AbiGlob), not a string the author types. See docs/content-key.md.

    substitute ¶

    substitute(bindings)

    Return a copy with {name} bindings applied where meaningful.

    FileData ¶

    FileData(path)

    Bases: DataAtom

    One logical path. It need not exist yet.

    Byte-hashed by default. A skin's typed subclass (brix.java.AbiFile) overrides content_key to fingerprint by meaning instead.

    GlobData ¶

    GlobData(pattern, exclude=())

    Bases: DataAtom

    A path set with optional named bindings, e.g. src/{name}.cpp.

    Byte-hashed by default; a skin's typed subclass (brix.java.AbiGlob) overrides content_key to apply a content lens to every matched file.

    Subtraction narrows membership: data.glob("{name}.cc") - "*_test.cc" returns a copy whose find drops files matching the fnmatch pattern(s) (*/?/[...], matched against the workspace-relative path, * crossing /). Membership only — substitution carries excludes through untouched, and the planner's edge inference ignores them (docs/content-key.md).

    RegexData ¶

    RegexData(pattern)

    Bases: DataAtom

    A path set matched by a regular expression with named groups.

    Prototype support is match-only: a regex collection can drive membership but cannot be used as a substitutable output template.

    substitute ¶

    substitute(bindings)

    Replace named groups with literal values, e.g. under expansion: (?P<video>[^/]+)/(?P<scene>[0-9]\S*) with video=intro becomes intro/(?P<scene>[0-9]\S*). Group bodies must not contain nested groups.

    ToolData ¶

    ToolData(name)

    Bases: DataAtom

    A tool identity, e.g. c++ or an absolute path.

    ValueData ¶

    ValueData(text)

    Bases: DataAtom

    Literal data that affects an output (options, flags, settings).

    DataUnion ¶

    DataUnion(*parts)

    Bases: DataExpr
